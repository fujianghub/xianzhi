# ADR-0050 任务按清单分组 · 文件夹聚合 · 相对日期快选 · Peek 停留触发与完整预览 · 任务页列宽

> 状态：已采纳 · 2026-10-07 · 修订 ADR-0044 §B.9（文件夹只能折叠 → 点文件夹聚合查看，箭头单独折叠）· §B.10（`group=date|priority|none` → +`list`，+search `folder`）· §C.13（日期快选 今天 / 明天 / 下周一 / 无日期 → +相对日期一行）、04 §6 与 REQ-UI-007（悬停 600ms → 停留 1s）。无迁移。需求区 00：REQ-TASK-042 · 043；REQ-UI-007 注。

## 背景

用户（2026-10-07）：「任务支持清单聚合分类，以清单的分类的形式展示；任务日期选择支持快捷键（比如 近一周、近 2 周、一个月、半年、一年）；鼠标一放到任务上就会弹框，不要立即弹出，弹出时应该显示所有（任务记载的东西不多），顺便优化排版；任务列表和边栏间隔太远，留着大片空白。」

现状：任务页只能按日期 / 优先级 / 不分组；左栏文件夹点了只折叠，看不到「这个文件夹里的全部任务」；日期快选只到下周一；任务行悬停 600ms 就开 Peek（鼠标扫过列表、在行上移动去点胶囊都会触发），Peek 只有状态 / 优先级 / 截止 / 指派四项 + 截断 12 行的纯文本描述；列表列 `mx-auto max-w-3xl` 居中，1440 以上清单栏与列表之间空出几百像素。

## 决定

### A. 按清单分组 · 文件夹聚合（REQ-TASK-042）

1. 分组方式 +「按清单分组」（`group=list`）：组序同左栏清单树（文件夹内的清单跟在文件夹后，组标题带色点、文件夹名作灰色前缀），末尾「未归类」；清单缓存里没有的（他端刚建）按任务带的清单补在后面。组内「+ 添加」带该组清单（「未归类」组 = 不归类）。
2. 只有非空的清单组是拖放落点（拖进 = 归入该清单）；空清单组不在拖动中冒出来——几十个清单时会推挤布局、让落点移位；归到任意清单仍用左栏。「未归类」组始终可落（= 移出清单）。
3. 点左栏文件夹 = 聚合查看其下全部清单（search `folder=<id>`，默认按清单分组、没有「未归类」组），文件夹前的箭头单独折叠；窄屏胶囊条也列出文件夹。页头 = 文件夹图标 + 名 + 其下清单计数之和。
4. 服务端：`GET /tasks?listId=<文件夹 id>` 展开为该文件夹下本人的清单（`inOwnListSql` 加本人文件夹子查询，查询数不变）；别人的文件夹 id → 空。文件夹本身仍不能作归类目标（create / patch 422），所以文件夹视图页顶快速添加带文件夹里第一个清单。
5. 分组方式本机记住（`localStorage xz.tasks.group`，只在 URL 不带 `group` 时用；已完成默认不分组、文件夹默认按清单）；单个清单视图不提供「按清单分组」，URL / 记忆带来的 `list` 回落按日期（换范围时 `group` 会被带过来，按范围纠正而不只是藏选项）。（注 2026-10-07：缺省改为一律按清单分组、单个清单回落不分组，记住键 `xz.tasks.group.v3`，见 ADR-0051。）

### B. 相对日期快选（REQ-TASK-043）

6. 日期选择器（快速添加 · 行内日期胶囊 · 批量条 · 详情「截止」共用 `DuePicker`）在 今天 / 明天 / 下周一 / 无日期 下加一行：**1 周后 · 2 周后 · 1 个月后 · 半年后 · 1 年后**，每格下方显示目标日（跨年带年份），当前截止正好是该日时高亮。用户说的「近一周 / 近 2 周」按截止日期语义理解为「一周后 / 两周后」（任务日期是截止点，不是区间）。
7. 按月的保留日、溢出取当月最后一天（1/31 + 1 个月 = 2/28 或 2/29），`shared/tz.ts addMonthsKeepDay`；单个管理菜单（⋯ / 右键）的日期区同样加这一行（保留原时刻，无则 23:59）。
8. 详情「截止」由 `datetime-local` 改为同一个 `DuePicker`（弹层关闭时一次提交），显示用用户时区；「计划」暂保留原输入。

### C. Peek：停留触发 · 完整预览（REQ-UI-007 注）

9. `useHoverIntent` 改为**停留意图**：指针在元素上静止 1000ms 才触发，移动（> 4px）即重新计时、移开取消；触发过或按下过鼠标后，直到移开前不再计时（关掉 Peek 后原地动一动不会又弹、点胶囊 / 改名时不弹）。Peek 已开着时换到另一行只需停留 350ms（行内取 `usePeek.getState()`，不让每行订阅 Peek，保住万行列表的 memo，REQ-UI-017）。全站共用（任务行、看板卡片、记录卡片、搜索结果）。
10. 任务预览摊开全部内容：空间 · 状态胶囊 → 标题（父任务）→ 属性（优先级 · 指派给 · 截止〔彩色日期胶囊〕· 计划 · 清单 · 预估 · 标签，空值「—」）→ 完整描述（`PmView` 只读渲染段落 / 列表 / 待办 / 代码，不截断）→ 子任务（完成数 / 总数）→ 创建 / 更新 / 完成时间。子任务与详情共用同一查询键。描述用紧凑只读正文 `.xz-prose-compact`（不撑 `xz-prose` 的 12rem 最小高度、不跟阅读字号）。

### D. 任务页列宽

11. 列表列去掉 `mx-auto`、`max-w-3xl → max-w-5xl`，左对齐贴着清单栏（只隔页边距）；更宽的屏幕空白留在右侧（≥ 1440 时那里是常驻详情栏）。

## 候选与否决

- **「近一周」做成按日期区间的筛选**（最近一周 / 两周 / 一月内到期）：任务页已有「最近 7 天」智能清单，用户原话是「日期选择支持快捷键」，指选日期时的快选——按快选实现；区间筛选如需要另起。
- **文件夹用 `list=<id>` 复用**：省一个参数，但列表缓存未到前不知道是清单还是文件夹（标题、默认分组、快速添加预设都要等），改用独立 `folder`。
- **组头计数用 `counts.lists`**：清单计数口径是「在我的清单里」（含指派给别人的），与「全部」视图的人员口径不同，会对不上——组头仍数已加载的行，同其它分组方式。
- **悬停延迟只调长到 1.2s、不看是否静止**：扫过列表仍会在停下的那一行误弹，且在行上移动去点按钮也会弹——改为停留意图。
- **Peek 去掉、只留详情栏**：Peek 是只读速览，不改 URL，键盘 `p` 与看板 / 搜索仍依赖——保留，改触发与内容。
