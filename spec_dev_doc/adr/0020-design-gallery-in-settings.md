# ADR-0020 设计画廊挪进设置、画廊自带用法

> 状态：已采纳 · 2026-09-27 · 修订 04 §8 / 08 §1 中画廊的路由与入口位置；画廊内容规格（04 §8、06 §10）不变，只做补齐。

## 背景

`/design` 画廊的入口挂在主侧栏「视图」组里，与今日 / 收件箱等日常视图并列，而它只是 admin 对照样式、做截图回归的内部工具，普通使用中用不到，放在主导航里既占位又让人困惑「这是干什么的」。画廊本身也不自解释：深浅并排只能手输 `?theme=both`；`motion` / `transparency` 两个 search params 被解析却没有接上；04 §8 要求的「色板含对比度值」「动效示例可切档位」未实现；近几轮新增的领域视觉（类型色块、9 色板、燕印、目录引导线）不在画廊里。

## 决定

1. **路由与入口**（REQ-UI-039）：画廊改为 `/settings/design`，嵌在设置布局内，入口放在设置二级导航「工作区」组末尾（admin+，与成员 / 审计同级的管理工具）。主侧栏移除画廊入口。旧 `/design` 保留为跳转路由，带原 search params 重定向，已有书签与文档里的链接不失效。权限不变：非 admin 404。
2. **画廊自带用法**（REQ-UI-040）：
   - 标题下一句说明「这页是什么、什么时候看」，每页一句「看什么」，页脚给出更新截图基线的命令。
   - 工具栏：主题 当前 / 日场 / 夜场 / 并排（`theme`）、动效档位 减弱 / 标准 / 丰富（`motion`）、降低透明度（`transparency`）。三者都进 URL，可分享、可被 e2e 直接打开。`motion` / `transparency` 写 `html[data-*]` 只在画廊内临时生效，离开画廊恢复本机偏好（`lib/motion.ts`），不写 `localStorage`。切换页原有两个模拟勾选框改为同一套 search params 的另一个入口。
   - Token 页对比度表：运行时从当前主题容器读 token、用 canvas 归一颜色，按 06 §7 的门槛（正文 7 / 次要 4.5 / 弱化与图标 3）算纯底板与纸面上的对比度并标达标；9 色板胶囊附对比度值。「最坏合成底」仍以 `scripts/check-contrast.ts` 为准，画廊不重复那套玻璃叠加模型。计算函数抽到 `src/shared/contrast.ts`，脚本与画廊共用。
   - 组件页补齐领域视觉：`KindIcon` 四档尺寸、`KindBadge`、9 色板 `IconChip`、燕印三档、静态目录树（`TreeGuides` + 字重分级，不请求数据）。
   - 页内网格改用容器查询（`@container`），嵌进设置内容区与深浅并排两栏时按实际宽度排版。

## 候选与否决

- **只把链接挪进设置、页面留在 `/design`**：点进去后设置导航消失，只能靠后退返回——否决。
- **画廊默认深浅并排**：同屏 blur 会超过 06 §8 的 6 个上限——否决，维持默认只渲染当前主题。
- **对比度直接调用 check-contrast 的最坏合成底模型**：需要在浏览器里复刻 glow / glass 叠加顺序，重复且易漂移；画廊只展示可见的纯底结果，门槛判定仍以 lint 为准。
