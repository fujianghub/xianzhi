# ADR-0060 「皮肤」改称「主题」· 设置 → 主题页 · 默认主题

> 状态：已采纳 · 2026-10-12 · 修订 ADR-0059（界面称呼、入口位置、认证页不套主题）、ADR-0049 §5（外观入口从「个人」与「工作区信息」移到「设置 → 主题」）、glossary「主题」词条。无迁移。需求区 00：REQ-UI-062 ~ 064；REQ-UI-060 注。

## 背景

用户（2026-10-12）：「我使用 http://172.16.12.51:3010/ 没看见，此外名称应该为主题，放在设置-主题 而不是合并到哪儿。支持默认主题设置」

1. **看不见**：3010 由 systemd 起，`DATA_DIR=./data/dev`；`pnpm xz skin install` 不读 systemd 环境，按默认 `./data` 装到了 `data/skins`。已挪到 `data/dev/skins`；CLAUDE.md 补注 3010 的数据目录。
2. 「皮肤」这个叫法用户不认，应叫「主题」；外观项散在「个人」与「工作区信息」两页。
3. 需要默认主题：管理员设、个人可回到默认、未登录页也用。

用户拍板（2026-10-12）：日场 / 夜场改称「明暗模式」；全部外观项挪到「设置 → 主题」；默认主题三项都要（管理员在卡片上设默认、个人「恢复默认主题」、登录 / 注册页套默认主题）。

## 决定

### 1. 称呼（界面层；代码标识符不变）

1. ADR-0059 的「皮肤」在界面上一律叫 **主题**（`ui.skin.*` 文案：主题 · 退出主题 · 设为默认 · 恢复默认主题 · （随主题））。代码、接口、存储仍叫 `skin`（`/skins`、`appearance.skin`、`html[data-skin]`、`DATA_DIR/skins`、`pnpm xz skin`），避免一次无收益的大改名。
2. 原「主题」（`data-theme = light | dark`、`appearance.theme`）界面上改称 **明暗模式**（日场 / 夜场 / 跟随系统）；顶栏按钮提示「切换明暗」，主题生效时为「退出主题」。

### 2. 设置 → 主题（REQ-UI-062）

3. 新路由 `/settings/theme`，设置导航第二项（个人之后）。页面：主题画廊 →「明暗与界面」（明暗模式 · 密度 · 动效 · 玻璃强度，`profile-*` testid 不变）→「恢复为工作区默认」→（所有者 / 管理员）「默认外观」。
4. 「个人」页只留账号资料、时区、周起始、语言；「工作区信息」页只留名称 / slug。

### 3. 默认主题（REQ-UI-063）

5. 所有者 / 管理员在每张主题卡片上「设为默认」：写工作区 `settings.appearance.skin`（`PATCH /workspace`，`workspace.manage`，记审计 `workspace.settings_changed`），本人生效值随之重算；默认卡片标「默认」。默认外观的明暗 / 密度 / 动效 / 玻璃强度在同页「默认外观」区设置。
6. 个人选过主题时出现「恢复默认主题」：删除本人 `skin`（PATCH `skin: null`），回到工作区默认。

### 4. 登录 / 注册页套默认主题（REQ-UI-064）

7. 公开接口 `GET /api/v1/skins/default`：返回工作区默认主题 `{ skin: { …summary, css } | null }`（未设 / 未安装 → null，`no-cache`）。默认主题的 `/art` `/thumb` 允许未登录读取（`public` 长缓存），其余主题与列表 / 详情仍要登录。`default` 加入保留 id。
8. 认证页（登录 / 注册 / 邀请）挂载时拉取并挂上默认主题，写本机 `xz:skin-default`；`theme-init.js` 在认证路径读它、其余路径读 `xz:skin`，两边首帧都不闪。回到工作台由外观同步换成本人生效主题。
9. 挂载 / 缓存逻辑拆到 `lib/skin-dom.ts`（不依赖 API 客户端），认证页只引它，首屏包不受影响。

## 影响

- e2e：外观用例改到 `/settings/theme`；`e2e/skins.spec.ts` 覆盖设默认 / 恢复默认 / 登录页默认主题，用例前后清空工作区默认外观（共享库）。
- 认证页右上角的明暗菜单在默认主题生效时只记住选择、不改页面（同 ADR-0059 §15）。
- 不做：主题的明暗两套；每个工作区多个默认主题。
