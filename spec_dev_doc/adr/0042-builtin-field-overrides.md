# ADR-0042 内置字段覆盖层：隐藏 · 显示名 · 选项名与色 · 顺序

> 状态：已采纳 · 2026-10-01 · 修订 ADR-0017 §3（内置类型「属性 schema 由代码定义」→ 代码字段可经覆盖层隐藏 / 改显示名 / 排序）、ADR-0036 §A.2（`entry_kind_overrides` 只能追加字段 → 另可覆盖代码字段）、ADR-0033 §A（路由层 strict 校验含必填 → 路由层不查必填缺失，由 service 按覆盖层查）。迁移 0025。需求区 00：REQ-ENTRY-034 ~ 037。

## 背景

用户（2026-10-01）：「类型字段需要支持内置类型字段的增、删、改、查；空间对应的类型字段位置（概览）以及其他相关地方也要一起做动态适配，只显示我定义的字段。」

现状：内置类型（Bug / 迭代 / 计划…）的字段写在 `entryFields.ts` 的 strict Zod 里；所有者只能**追加** x 字段（ADR-0036），代码字段删不掉、改不了名。概览、表格、卡片、看板、统计、查询块、批量栏里还有多处按字段名写死的展示。

用户当场拍板四项：

1. 深度 = **覆盖层**：字段键与选项值不变（统计 / 筛选 / 流转 / 看板靠它们），只覆盖显示；「增」= 已有的追加字段。
2. 隐藏已有数据的字段 = **保留旧值，只隐藏**（可逆）。
3. 必填且无默认值的字段（迭代起止、变更版本 / 发布日期、复盘周期）**也允许隐藏**，隐藏即变可选。
4. 仍是工作区统一、仅所有者维护（沿用 ADR-0017）。

## 决定

### A. 数据（迁移 0025；01 §3.4c）

1. `entry_kind_overrides + base_fields jsonb not null default '{}'`：字段名 → `{ hidden?, label?, options?: { 值 → { label?, color?, hidden? } } }`（`src/shared/schemas/baseFields.ts`，前后端共用）。
2. `entry_kind_overrides + field_order jsonb not null default '[]'`：内置字段名与追加字段 x 键混排；未列出的按代码顺序排在后面；追加字段增删后去掉失效键。
3. 规范化（service `normalizeBaseFields`）：字段名须属该 kind；只有选项字段能改选项、选项值须在枚举内；**默认值选项不能隐藏**，每个选项字段至少留一个可见选项；显示名 1–20 字，与其它覆盖名及追加字段名不重复；空项去掉。自定义 / 空间类型不适用（它们的字段本就是定义出来的）。

### B. 校验与数据

4. 路由层 `entryFieldsIssues` 只查未知键与已给出的值，不查必填缺失（它不知道工作区覆盖）；service `resolveKindFields` / 模板 `checkFields` 按覆盖层做完整校验：被隐藏的必填字段有默认值（`defaultEntryFields`）则补默认，无则改为可选（`entryFieldsSchema(kind, optional)`：strict 形状 `.partial` 后重套跨字段检查——zod 4 不允许对带 refine 的对象 `.partial()`，故形状与检查分开定义）。错误路径不变 `fields.<键>`。`kindWithFieldsSchema` 仍按代码默认全量校验（`requireAll`）。
5. 同类型改属性（`PATCH /entries/:id` 的 `fields`、批量 `fields`）：请求里没带的被隐藏字段并回原值；改类型不并（旧类型的键在新类型里可能未知）。
6. 改类型 / 删类型的转入目标：`fieldsForRetype`、`resolveMoveTo` 与前端 `defaultsSatisfy` 按目标类型的覆盖层判定。
7. 不写审计、不写流转：覆盖层只改展示，与改名 / 改色一致。导出 frontmatter 照常输出全部键（给机器读，不丢值）。Bug 的 `normalizeBugFields`（优先级补 p2、发现 / 解决日期）照旧维护，隐藏的只是展示。

### C. 前端

8. 统一出口 `useFieldSpecs`：`baseSpecsOf(kind, meta, t)` 套上隐藏 / 显示名 / 选项名与色 / 选项隐藏标记，再与追加字段按 `fieldOrder` 排序，最后套模板元数据（ADR-0039）。选择器 / 筛选 / 批量菜单用 `pickableOptions`（去掉隐藏选项，当前值保留）。
9. 各展示处一律从规格取：空间概览状态概要条（隐藏状态 → 无；隐藏选项仅有计数时出现；Bug 按优先级排序仅优先级可见时）、`EntryTable` 状态 / 进度专列与表头、`EntryCard` 关键字段（隐藏的不占名额）、看板列（隐藏状态 → 无看板；隐藏选项仅有卡片时出列）、记录页分组 / 排序 / 统计视图、`BugStats` 各卡片、查询块设置与统计视图、`EntryBatchBar`、属性栏与流转时间线、`EntryRelations` 状态文字、迭代 / 变更时间线、新建对话框。
10. 设置：`BuiltinFieldsEditor`（设置 · 类型的内置类型行「字段（N）」与空间 `SpaceTypesDialog` 的内置类型页）：每字段 眼睛切换 · 显示名（留空 = 默认）· 上下移（与追加字段混排）；选项字段逐项 色 · 显示名 · 眼睛（默认值选项禁用）；「恢复默认字段」。非所有者只读。

## 候选与否决

- **彻底数据化**（内置字段转成与自定义字段同构的定义，可删、可改类型）：Bug 统计、流转、迭代时间线、`normalizeBugFields` 都依赖固定键——工作量与风险最大，用户否决。
- **覆盖层 + 状态可增删**：需给每个状态标「未关闭 / 已关闭」并改造统计与解决日期维护，约 +40% 工作量，用户暂不要。
- **隐藏即清空旧值**：不可逆，用户否决。
- **只允许隐藏有默认值的必填字段**（审查建议的保守版）：改动更小，但迭代起止等五个字段始终显示，不满足「只显示我定义的字段」，用户选择放开。
- **导出也去掉隐藏字段**：导出 / 导入即丢值，与「隐藏保留数据」矛盾——否决。
- **新增审计 action**：覆盖层不动数据，与改名 / 改色一致不审计——否决。

## 后果

- 迁移 `0025_builtin_field_overrides.sql`（两列，默认值即旧行为，无数据迁移）。
- 00：+REQ-ENTRY-034 ~ 037。01 §3.4c；02 §9 `/entry-types/builtin/:kind` 行；08 §2.13 设置 · 类型、§2.5b 空间类型对话框；glossary +内置字段覆盖。
- shared `schemas.test` 中「createEntrySchema 缺 severity 即 422」改为路由层放行、service 422（API 测试 REQ-ENTRY-001 路径不变）。
- `entryQuery` 查询块与保存视图不受影响（键与值不变）；被隐藏字段的条件照常生效，只是设置对话框不再列出该字段。
