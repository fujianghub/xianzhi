# ADR-0040 模板属性并入记录页的筛选与分组

> 状态：已采纳 · 2026-09-30 · 修订 ADR-0039「候选与否决」中「模板字段并入记录页筛选 / 分组选项——本轮不做」一项（→ 采纳）、§B.14 `GET /templates/fields` 的返回（+`name`）。无迁移。需求区 00：REQ-ENTRY-033；REQ-TPL-019 加注。

## 背景

ADR-0039 让模板有了自己的属性，记录页的表格也会为它们加列，但筛选下拉与分组选项仍只列类型字段——看得到「进展」这一列，却不能按它筛、按它分组。用户（2026-09-30）：「把模板属性并入记录页的筛选和分组选项」。

服务端本来就不挡：列表 `fields=` 与 `/entries/stats groupBy` 对任意 x 键生效（ADR-0036 §D.23），缺的只是界面上选项的来源。

## 决定

1. **选项来源**：记录页选中**单一类型**时（与类型字段的筛选 / 分组同一前提），把「绑这个类型的模板」的自有字段并进来——
   - 筛选下拉：单选、多选（多选按「含」筛，同 ADR-0036）；
   - 分组选项：单选（多选不参与分组，同 ADR-0036）；
   - 排在类型字段之后；同键只留一个（「复制到我的」的副本与原模板同键）；与类型字段撞键的以类型为准。
2. **来源取元数据目录**（`GET /templates/fields`，ADR-0039 §B.14），按模板所绑的 `(kind, typeId)` 匹配，**不**取决于已加载的行——否则筛到没有结果时选项跟着消失，刷新 / 保存视图后也不稳定。
   - 正在用的键（当前 `fields=` 或 `group=`）即使其模板不绑这个类型也保留，URL / 保存视图里的条件不会变成看不见的筛选。
   - 代价：改过类型的记录，其来源模板若不绑当前类型，它的模板属性不出现在筛选里（表格列仍按行显示）。
3. **同名区分**：同一类型下两个模板各有一个「阶段」（不同键），或与类型字段同名时，选项写成「阶段（模板名）」。为此目录每项 +`name`：**只对读者读得到的模板给出**；只因「看得到用它建的记录」才进目录的别人的个人模板为 `null`（不泄露模板名，此时不加后缀）。
4. **表格分组头**：分组键是模板属性时，`EntryTable` 由调用方给出该键的规格（组序 = 选项顺序，缺值组在最后；彩色胶囊同其它字段）。
5. 不迁移：模板属性改名 / 删选项后，保存视图与 URL 里的旧条件匹配为空，由用户自行改（同 ADR-0036 §A.11）。查询块（`entryQuery`）的字段条件本轮不动（它现在也只列内置枚举字段）。（注 2026-10-01：查询块的条件已由 ADR-0041 接入模板属性与类型追加字段。）

## 候选与否决

- **选项取自已加载行的来源模板**：与表格列的做法一致，但筛选后行变了选项也变，保存视图打开时可能看不到自己的筛选条件——否决，只作为「保留正在用的键」的兜底思路（改为从目录按键找）。
- **不区分同名**：两个「阶段」下拉并排，无从分辨——否决。
- **目录对所有项都给模板名**：别人的个人模板名会经由一条共享记录泄露——否决。
- **跨类型（未选类型时）也列模板属性**：类型字段在未选类型时同样不列，保持一致。

## 后果

- 02 §9 `GET /templates/fields` 每项 +`name: string | null`。
- 前端：`lib/template-fields.ts`（`typeTemplateFields` 纯函数）、`EntriesPage` 的筛选 / 分组选项、`EntryTable` 的 `group.spec`。
- 同一类型下带属性的模板很多时，筛选条上的下拉会变多（每个单选 / 多选属性一个）。
- 00 +REQ-ENTRY-033；08 §2.8 注。
