# ADR-0034 认证页「衔枝小院」：双栏插画 + 会反应的小燕

> 状态：已采纳 · 2026-09-29 · 取代 06 §5.6「登录页 = 居中卡片」一句、兑现 ADR-0007 预留的「登录页大插画（柳枝构图 D）」；补充 08 §2.1 / 2.1b / 2.2 与 `/login/2fa`。需求 00 §16 REQ-UI-041 ~ 043。

## 背景

登录页原为一张居中 `glass-thick` 卡片（燕印 + 表单 + 拼图滑块），干净但缺少品牌情绪。用户要求「质感、动效、UI、交互、可爱、生动」，给了三份参考：

- **简斋登录页**：双栏玻璃卡，左栏水墨小猫由手写弹簧引擎驱动（视线跟随、捂眼、偷看、摇头、成功盖章、待机小动作、入睡、撸猫），`data-mood` × `data-behavior` 切表情，三档动效降级。
- **animatedlogin**（guohaolian）：状态优先级 + 声明式姿态 + CSS 过渡补间；扭头不看密码、显示密码时偷看、出错垂头 + 阻尼摇头。
- **login-demos**（sunyctf）：熊猫抬爪遮眼（爪子挂在表单上）、毛玻璃漂浮、出错气泡。

三份都没有「登录成功」的角色戏。

## 决定

### 1. 形象与构图（用户选定）

- 吉祥物是**小燕**，不照搬猫：它与燕印、「衔枝筑巢」同源（ADR-0004）。画面只有三样——垂柳从卡片顶上挂下来、一根横枝、小燕立在枝中间，这就是 ADR-0007 预留的柳枝构图 D。**不画燕巢 / 雏燕**：初版画过，用户评审认为元素太多、不聚焦（2026-09-29）。
- **造型：A「豆豆燕」**（2026-09-29 经三轮评审定稿）。
  - 前两版都画的正面：正面圆了像团子（被评「太胖」），拉长像保龄球瓶（被评「更丑」）。根因是视角——燕子的辨识度（流线身、长刀翅、深叉剪刀尾）只在侧面 / 3/4 侧面看得见。
  - 做了三个方向给用户挑（A 萌系 3/4 侧身 · B 燕印扁平几何 · C 工笔侧影），用户选 A。
  - A 的要点：头身一体的豆子形（无脖子）、黑豆眼 + 腮红；燕子特征交给分层长刀翅（覆羽 + 三枚飞羽）与前后两根剪刀尾。
  - 面部按家燕：**栗红下巴 → 藏蓝胸带 → 暖白腹**。单独一道红围兜会被看成张开的嘴，放大成红脸又像小丑鼻子；是胸带把红喉框住，才读作燕子。
- **跟随与去机械感**（第八轮，2026-09-30；评审「鼠标移动不跟随、动作呆板、嘴像画了两遍」）。
  - 量化诊断：原先眼珠最多动约 2px；头部转角与指针方向对不上（随机歪头淹没了跟随）；不会抬头低头，指针到背后也不转身。
  - 改法：
    - 头绕颈旋转、让喙指向目标（±26° 抬头 / 低头）；
    - 指针越过小燕背后约 0.45 个插画宽度就转身（根节点 `data-facing="back"` 触发 head-fx 翻转，带回差，转头时眨眼；捂眼等情绪强制面朝前）；
    - 眼珠行程加大到约 4px，高光只跟 35%（视差）；
    - 感应距离随插画尺寸缩放；
    - 大幅换目标时扫视（眼先头后），小幅变化连续平滑跟随。
  - 活物感：
    - 眼 → 头 → 身 → 尾 的弹簧由快到慢形成跟随链，尾巴随身体倾斜速度反向回弹；
    - 平静时有头部微顿挫、眼珠微扫、胸部错相呼吸、偶尔换重心，间隔与幅度都随机化；
    - 情绪切换有预备冲量；成功时落影随跳跃伸缩。
  - 嘴：一个闭合小喙（带高光）+ 紧贴喙根的暖黄小圆角；红色口腔只在啾鸣 / 开心时露出。
  - 质感：翅下柔影、虹膜细环、眼底反光、更细更亮的头顶釉光。
  - e2e：标准档用例改为断言抬头 / 低头与转身 / 转回。
- **定稿：幼燕 + A 墨青**（第七轮，2026-09-30；取代下面的 N2「自然」与更早的豆豆燕）。
  - 评审意见：N2 太瘦、不可爱不生动，配色有问题。前几轮在「Q 版显胖」和「写实太瘦」两头摇摆，宝蓝身体又和暖色日出、翡翠主色互相打架。
  - 先调研后定样式（Taillow、Tsubakuro、Duolingo、シマエナガ、国潮春燕等），结论：画一只刚离巢的幼燕，天然介于可爱与写实之间。
  - 规格：头宽约为躯干长 45%；躯干是胖端在前胸的蛋形，保留颈胸腰起伏，前倾约 24°；眼径约头宽 26%，位于头高 56% 并偏向喙，主副两个高光；小三角喙，嘴角一道暖黄笑线；长刀翅收起伸到尾叉根；叉尾长度约为躯干 0.7，带两粒白斑，左右略错开。
  - 配色 A 墨青：背羽由高饱和宝蓝（约 222°）挪到低饱和墨青（约 205°），与翡翠主色成相邻冷色；额喉改陶土红，呼应日出；腹部用暖奶油色；夜场背羽提亮并加暖色轮廓光。场景同步调和：日晕降低饱和度，柳叶改鼠尾草绿。
  - 实现：头单独成块，与身共用绝对坐标渐变；轮廓光只打在身上（打在头上会发灰）；腹、腹影、胸带用身体 clipPath 收在轮廓内；捂眼仍是头部水平翻转（扭头躲开）。
  - 流程：样式规格、配色对照与实施计划先做成方案页给用户审（https://claude.ai/artifact/X4UFB6MBz2XD1VoeoLN3CN），通过后再落地。
- **比例：N2「自然」**（已被上一条取代）（第六轮评审「太丑、要偏瘦更自然」，取代 A「豆豆燕」的 Q 版比例）。
  - 根因：拆头后头成了大圆球顶在豆子身上，像大头娃娃；Q 版比例（大头、圆身、大黑豆眼）本身就与「自然」相反。
  - 改按真家燕比例：修长鱼雷身（身长约为身宽 3 倍）、窄长刀翅收起伸过尾根、深叉尾带两根长飘带；栗红额喉、深色胸带、暖白腹。
  - 出三个档位（N1 写实 / N2 自然 / N3 灵动，只差头眼大小），用户选 N2：头眼比真燕略大一点，加一抹淡腮红。
  - **捂眼改为扭头躲开**：头绕颈水平翻转、喙转向背后、闭眼，翻转过渡正像转头；偷看是扭着头睁眼回瞄。不再用翅膀当手（写实比例下不自然）。
- **质感：T1「绒光」**（第四轮评审，三种渲染 T1 绒光 / T2 色线水彩 / T3 精修墨线 中选定）。
  - 不描边，形体全靠光影：主光在右上（日轮方向）；背羽钢蓝三段渐变；头顶一道釉光，右上边缘一层暖色反光；腹部左下转暖驼；枝上落一片柔影；眼睛是径向渐变 + 双高光 + 底部一道冷色反光。
  - 场景同一光源：树枝为锥形填充 + 树皮渐变 + 受光边，柳叶大小错落。
  - 待机加两路慢正弦叠加的重心轻晃（周期互质），只在平静时跑，减弱档不跑。
- **动作：按真鸟规律**（第五轮评审「呆」）。平滑弹簧一直在飘，所以显得呆。
  - **头身拆开**：头是独立的圆，绕颈转；身体只画到肩，上沿藏在头后，与头共用绝对坐标渐变，看不出接缝。
  - **扫视**：注视目标变化超过阈值才「提交」一次注视点，头快速甩过去再定住（头部稳定）；平时只做 1–3s 一次的小幅复视。
  - **先后层次**：眼珠最快（近临界弹簧），头晚约 60ms、快而略带回弹，身体最慢。
  - **生动细节**：提交注视点时一半概率歪头（单眼打量）；大角度转头时偶尔顺带眨眼；眨眼快闭慢睁，18% 双眨。
  - **预备动作**：捂眼先缩脖，出错先一怔。
  - **待机清单换成燕子停栖时真会做的**：张望、歪头打量、抬头看天、理羽（头埋向肩背、眯眼蹭）、啾鸣（喙快速开合三下 + 喉部一鼓一鼓）、抖羽、翘尾、伸翅（先收后展）、沿枝横挪。去掉原地蹦跳（燕子腿弱）。间隔缩短到 2.5–6s。
  - **动作实验台**：`/login?birdlab` 逐个触发情绪与小动作，只在开发环境出现，生产构建裁掉。
- 翅膀就是「手」：近侧翅绕肩翻上来挡左眼；远侧翅平时藏在身后，捂眼时从右侧升起挡右眼；偷看 = 只挡右眼、左眼偷看。头身一体不单独转头，「看」靠全身倾 + 五官整体挪 + 眼珠微移（标定写在脸部组的 `data-*` 上）。
- **成功 = 衔上一枝**：小燕眯眼笑、嘴里衔一根带嫩叶的枝、扑翅跳两下、星星闪。这一幕是本品牌独有的，参考里都没有。

### 2. 布局（REQ-UI-041）

- 登录 / 注册 / 2FA / 邀请四页共用 `components/auth/AuthShell`（用户选定：四页都用完整插画）。
- **≥ 900px**：一张宽 `glass-thick` 卡，左栏插画 + 小燕气泡，右栏表单；最宽 980px，右栏 440px。
- **< 900px**：只留表单卡，小燕从卡片顶沿探头，两只翅尖扒在卡沿上。整幅插画**不挂载**，移动端首屏（Lighthouse 以移动端计）不背它。
- 插画在卡片之内，不另加 `backdrop-filter`：同屏 blur 仍只有卡片 1 处。棱线加亮仍只在认证页（06 §5.6）。
- 燕印 `lg`、`sr-only` 标签、各 `data-testid`、拼图滑块结构都保持不变。

### 3. 情绪状态机（REQ-UI-042）

纯函数 `bird-mood.ts`，优先级 **success > error > cover > peek > captcha > scout > idle**。

| 情绪 | 触发 | 表现 |
|---|---|---|
| idle | 无焦点 | 视线跟随指针、眨眼、呼吸；气泡是各页的招呼语 |
| scout | 焦点在文本框 | 歪头凑向输入框，视线沿光标走，每按一键点头；账号类字段在气泡里回显名字（≤ 8 字） |
| cover | 焦点在密码框且为密文 | 长翅从身侧翻上来捂眼、脸红 |
| peek | 密码为明文且有值 | 放低右翅从翅缝里偷看，星星闪 |
| captcha | 焦点在滑块（未解开） | 视线跟着手柄，尾巴轻摆 |
| error | 页面 `fire('error')` | 垂头、羽冠炸起、眉眼下垂含泪、冒「?」、阻尼摇头，2.4s 后平复 |
| success | 页面 `fire('success')` | 衔枝欢跳；约 0.9s 后页面再跳转（减弱档不等） |

- 表单信号由外壳自己读：`focusin` / `focusout` / `input` / `click` / `pointerup`。密码框标 `data-secret`，切成明文后仍能认出。页面只负责在提交失败 / 成功时调用 `fire()`。通行密钥取消不算出错。
- 小动作（`data-behavior`）由引擎调度：
  - 待机时每 4–8.5s 随机一个：张望、啾鸣 ♪、甩尾、伸翅、跳一下；
  - 20s 无操作入睡（zZ），任何操作唤醒并伸懒腰；
  - 点小燕：第一下害羞捂脸，1.6s 内再点冒心。
  - 害羞 / 冒心能打断捂眼与偷看；出错 / 成功时一律不显示小动作。
- 整张插画 `aria-hidden`，气泡也是装饰；错误照旧由表单的 `role=alert` 播报。点击热区不可聚焦，只是指针彩蛋。

### 4. 实现与动效档位（REQ-UI-043）

- **纯 SVG + 一个 rAF 引擎**（`bird-engine.ts`），不引入新依赖。
  - 三层弹簧：瞳孔 k320/c28 → 头 k110/c13 → 身 k48/c9，做出跟随的先后感；dt 上限 1/30，防掉帧后爆冲。
  - 瞳孔用椭圆限幅；歪头 ≤ 6°，scout 时额外 ±7°。
  - 引擎只写 `data-part` 节点的 `transform`，并缓存上次的值，值不变不重写。
  - 情绪姿态与关键帧由 `styles/auth.css` 用**独立的** `rotate` / `translate` / `scale` 属性叠加，和引擎写的 `transform` 不互相覆盖。
- **档位**（用户选定：标准档含全部角色戏）：
  - `reduce`：不起循环，姿态由 CSS 一步到位（时长 token 归零）；关键帧全停，含义性符号（? / 泪 / zZ / 心）静态显示；
  - `standard`：全部角色戏 + 垂柳轻摆；
  - `rich`：再加柳叶飘落。
  - 系统 `prefers-reduced-motion` 优先于用户选的档位。
- **性能**：
  - `auth.css` 与引擎随认证路由拆包，不进首屏；
  - 引擎在 `requestIdleCallback` 之后才启动，页面隐藏时停；
  - 不用 `will-change`；左栏 `contain: paint`。
- **颜色**：新增 `--xz-bird-*` `--xz-scene-*` `--xz-willow*` `--xz-branch`，日场、夜场各一套。夜场燕身提亮并加浅色描边，日轮换成月轮。这些都是纯装饰，不承载文字，不进对比度矩阵。
- **遵守**：不变量 5（色值 / 动效只取 token，档位只经 `lib/motion.ts` 的 `effectiveMotion()`）；06 §5.2「错误不抖动」（卡片不抖，摇头的是角色；拼图滑块原有的抖动不变）；06 §8（blur 数不变，无 will-change）。

## 后果

- 四个认证页有了统一的品牌情绪。以后改认证页的外观，只改 `AuthShell` / `auth.css`，页面只写表单。
- 性能：首屏集合不变（`check-budget` 首屏 166.8 KB / 250 KB，认证页 chunk 不在其中）。本机 Lighthouse 移动端 A/B（同一 gzip 静态服务、同一机器）：main 与本改动都是 59 分，FCP 同为 7.4s，LCP 7.8s → 8.0s。本机绝对分受环境影响，生产栈仍以 `e2e/infra.spec.ts`（≥ 90）为准，部署后须复测。
- e2e 注意：
  - 登录接口按 IP 每分钟 10 次（REQ-AUTH-012）。小燕的出错 / 成功用例用 `page.route` 模拟 `/api/auth/sign-in/**`，不挤占真实登录用例的额度。
  - 成功后多等约 0.9s 才跳转，`waitForURL` 的默认超时足够。
- 减弱档的 CSS 必须留在 `auth.css` 末尾，见 `debug/2026-09-29-auth-reduced-motion-specificity`。
