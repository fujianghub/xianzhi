# ADR-0003 一期工期基线改为任务级估时

> 状态：已采纳 · 2026-09-23 · 部分取代 ADR-0001 §7 与 §9.5 的工期数字；ADR-0002 §后果的「+1 天」一并取代。
> 计划值：`spec_dev_doc/tasks/phase-0.md`、`tasks/phase-1.md` 文末的脚本求和。

## 背景

ADR-0001 §7 写 Phase 0 = 3 天、Phase 1 = 1.5 周；§9.5 因多用户与通知改为 5 天、2.5 周；ADR-0002 再加 1 天。2026-09-23 按 SDD 把 00 的 217 条需求拆成任务并逐条估时后，Phase 0 约 106.5 h（≈ 13 个工作日）、Phase 1 约 174 h（≈ 22 个工作日），是 ADR 数字的 2 倍以上。三个数字并存会让里程碑承诺失真。

## 候选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 维持 ADR §9.5 数字，砍范围凑天数 | 承诺不变 | 需砍掉的都是 P0（认证、协同、通知闭环），砍完不可用 |
| B. 采用任务级估时，范围不动 | 计划真实 | 一期从 5 周变约 9 周 |
| **C. 采用任务级估时为计划值，P1 尾巴顺延到下一 Phase 首周** | 计划真实且 P0 路径可控（Phase 0 ≈ 90 h、Phase 1 ≈ 120 h） | 仍约 7–8 周；顺延项需在下一 Phase 任务表登记 |

## 决定

采用方案 C：

1. **工期计划值 = `tasks/phase-N.md` 文末的脚本求和**，任务表是唯一权威；ADR-0001 §7 / §9.5 与 ADR-0002 的天数保留为历史记录，不再引用。
2. 每个 Phase 的验收以 00 中该 Phase 的 P0 REQ 全部有通过测试为准（05 §5），P1 完成率 ≥ 80%，其余带编号顺延。
3. 顺延项清单写在各 tasks 文件的「裁剪建议」段；顺延即在下一 Phase 任务表新增任务，不得静默丢失。
4. 估时偏差 > 30% 时更新任务表并在 CHANGELOG 记录，不再开 ADR。

## 后果

- 一期（Phase 0–2）总工期从约 5 周改为约 8 周；Phase 2 任务表在 Phase 1 结束前编制。
- 05 §11 Phase 0 验收清单与 tasks/phase-0 对齐（`pnpm gi export` 移到 Phase 1 验收）。
- CLAUDE.md 不需改动；05 头部「一期约 5–6 周」改为指向本 ADR。
