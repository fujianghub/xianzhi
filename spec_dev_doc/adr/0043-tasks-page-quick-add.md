# ADR-0043 任务页：滴答清单式列表 · 快速添加智能识别 · 详情贴图

> 状态：已采纳 · 2026-10-01 · 补充 08 §1 路由表（+`/tasks`）与 §2.3b 任务页、02 §9 `GET /tasks` 的 `view=mine`、03 §7 liteKit 描述可贴图。需求区 00：REQ-TASK-025 ~ 028。

## 背景

用户（2026-10-01）：产品开发中的 Bug、迭代优化值得一条一条单独成文档；但生活 / 学习的待办往往几个词就说完，再用「一条记录 = 一篇文档」太笨重。希望优先用列表（主题、状态、详情），需要时再点进条目编辑详情（文字、图片、链接），参考滴答清单。

探查结论：工程里早有一套独立于记录的**任务**（`tasks`，01 §3.2）——标题、6 态状态、优先级、截止、标签、子任务、轻量富文本描述（liteKit PM JSON，不走 Yjs），并有今日 / 收件箱 / 看板 / 日历。缺的是：侧栏没有「全部任务」入口（任务藏在空间页签里）；列表顶部没有常驻的快速添加；描述里插不了图片（服务端已支持任务附件，前端上传写死为记录）。

用户当场拍板：复用「任务」，不新建记录类型；任务页按日期分组 + 快速添加智能识别。

## 决定

### A. 数据与接口（REQ-TASK-025）

1. **不改表**。`GET /tasks` 的 `view` 增 `mine`：`mine()`（指派给我，或未指派且由我创建——与今日同口径）∧ 顶层任务（`parent_id is null`）；可叠加 `status` / `spaceId` / `tag` / `sort`。任务页用 `status=inbox,todo,doing,blocked&sort=dueAt`（无截止排在最后，沿用现有 `coalesce(…,'infinity')`）与 `status=done&sort=-updatedAt`（最近 50 条）。
2. 列表本就带 `hasDescription`（不返回正文列，不变量 6）。

### B. 快速添加（REQ-TASK-026）

3. `src/shared/quick-add.ts` 纯函数 `parseQuickAdd(input, today, ignored)`：日期（今天 / 明天 / 后天 / 大后天 · 周X / 星期X（本周未过取本周，含今天）· 下周X（周一为一周起点）· M月D日 / M-D / M/D / YYYY-M-D（不写年且今年已过 → 明年；非法日期不识别），可跟 `HH:mm` 或「上午 / 下午 / 晚上 N 点（半）」；只取第一个日期）· `!紧急 / !高 / !中 / !低` → 4 / 3 / 2 / 1（与任务 priority 同向，区别于 Bug 的 p0）· `#标签`（多个）· `~空间`（一个）。识别片段从标题去掉；去掉后为空则整句当标题。`quickDueIso` 把日期转成用户时区的时刻，无时间 = 23:59（与日历 ALL_DAY、今日一致）。
4. `QuickAddTask` 组件：常驻一行输入，下方胶囊预览识别结果，× 取消识别（记原文，之后按普通文字）；回车即建、清空、焦点留在框内（提交时不禁用输入框，只防重复提交）；Esc 清空。标签按名匹配本人标签（ADR-0017），没有则 `POST /tags`（`colorFor(name)`，guest 不建）；空间按名匹配本人可写、未归档的空间（全名优先，其次唯一前缀），匹配不到则胶囊划线、落回默认空间。默认值取页面登记的 `useNewTask` 默认，识别结果优先。挂在任务页、今日、收件箱、空间任务列表（列表视图）顶部。`POST /tasks` 带 `Idempotency-Key`（`newId()`，不变量 6）。

### C. 任务页（REQ-TASK-027；08 §2.3b）

5. 路由 `/tasks`，侧栏「视图」在「今日」下「任务」。页头 → 快速添加 → 空间筛选（`?spaceId=`）→ 按截止分组：已逾期（早于今天 00:00，与今日同口径）· 今天 · 明天 · 未来 7 天（第 2 ~ 7 天）· 以后 · 无日期；组内截止早的、同一时刻优先级高的在前（`lib/task-groups.ts`）。组可折叠，记在 `localStorage`（仅本机便利，读写包 try/catch）。行 = 现有 `TaskRow` / `TaskList`（勾选完成、400ms 淡出、8s 撤销、j/k 键盘，焦点在组内移动）。
6. 点行 → 页内右侧 `TaskDetailSheet`（`?task=<id>`，同日历做法），列表不离开；详情里改标题 / 状态 / 优先级 / 截止 / 标签 / 描述 / 子任务 / 评论（均为现有功能）。
7. 已完成默认收起（`?done=1` 展开最近 50 条）。

### D. 详情贴图（REQ-TASK-028；03 §7）

8. `LiteEditor` 增 `uploadTaskId`：liteKit 描述变体加上传占位与文件拖入 / 粘贴插件（只接文件，其余粘贴照旧）+「插入图片」按钮；`uploadFiles` 目标泛化为 记录（带 ydoc，按编码大小软限）/ 任务（无 ydoc，按描述 JSON 大小对照 `MAX_JSON_BYTES` 100KB；只收图片）。上传完成插入 `image{src: xz:attachment/<id>}` 后**立即保存**（失焦保存可能已经发生）。评论不开（评论创建前没有 targetId）。

## 候选与否决

- **新建记录类型「待办」**：记录必带 Yjs 文档、较重，且与现有任务功能重复——用户否决。
- **按空间（清单）分组的双栏清单视图**：更像滴答的清单页，但「今天要做什么」看不直观；空间改为筛选——用户选按日期分组。
- **快速添加只收标题**：日期 / 优先级建完再点选多一步——用户选智能识别。
- **`!1…!4` 数字优先级**：与 Bug 的 p0（数字越小越急）方向相反，易混——不做。
- **一条虚拟列表带组头（j/k 跨组）**：要改 `TaskList` 的虚拟化与焦点逻辑；与今日页一致采用每组一个列表，焦点在组内移动。
- **子任务也平铺在任务页**：父子同屏会重复，子任务在父任务详情里看。
