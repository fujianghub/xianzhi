# ADR-0041 查询块的条件支持类型自定义字段与模板属性

> 状态：已采纳 · 2026-10-01 · 修订 ADR-0033（查询块设置里的条件只列内置枚举字段）、ADR-0040 §5（「查询块的字段条件本轮不动」）。无迁移、无接口变化。需求区 00：REQ-BUG-013；REQ-BUG-011 加注。

## 背景

用户（2026-10-01）：「把查询块也支持模板属性条件」。

查询块（`entryQuery`，ADR-0033）的 `query` 是记录页 search 白名单子集，服务端对 `fields=` 里任意 x 键都生效（ADR-0036 §D.23），记录页也已能按模板属性筛选（ADR-0040）。缺口只在设置对话框：条件下拉由 `fieldSpecs(kind)` 从内置 zod 字段推出，只有内置枚举——连类型追加的自定义字段（ADR-0036）都没有。

## 决定

1. 查询块设置里，选中类型后的**条件属性** = 该类型的单选 / 多选字段（内置枚举 + 类型追加的自定义字段）+ 绑该类型的模板的模板属性（单选 / 多选）。多选按「含」匹配（同 ADR-0036）。
2. 模板属性的来源、同键去重、同名带模板名、「正在用的键即使其模板不绑该类型也保留」，与记录页筛选完全一致（ADR-0040 §1 ~ 3）：抽成共用的 `useTypeTemplateSpecs()`（`FieldValue.tsx`），记录页与查询块都用它。
3. 条件下拉的标签与选项改用字段规格（`useFieldSpecs`）的显示名与选项名；Bug 状态仍保留「未关闭」（`new|pending`）这一项。
4. 查询块的类型下拉仍只有内置类型（与现状一致，本轮不加自定义类型）。
5. 查询结果按**阅读者**权限实时查询（ADR-0033 不变）：条件引用的模板属性，阅读者即使在目录里看不到它的定义，也照样按键筛选；块上不显示条件文字，不泄露属性名。
6. 不迁移：模板属性改名 / 删选项后，查询块里的旧条件匹配为空，由作者自行改（同 ADR-0036 §A.11）。

## 候选与否决

- **只加模板属性、不加类型追加的自定义字段**：两者对用户都是「属性」，只加一种反而奇怪；而且共用规格后两者是同一行代码——否决。
- **查询块里单独维护一份模板属性列表**：与记录页口径分叉——否决，抽共用 hook。

## 后果

- 前端：`EntryQueryView.tsx` 的 `QuerySettings`、`FieldValue.tsx` 新增 `useTypeTemplateSpecs`、`EntriesPage.tsx` 改用该 hook。
