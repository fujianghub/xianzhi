# ADR-0012 分类：大类、概览与类型视图、目录树、Bug ↔ 迭代关联

> 状态：已采纳 · 2026-09-26 ·（注：界面称呼已由 ADR-0013 改回「空间」）· ~~界面「空间」改称「分类」~~（大类之下的一层；代码 / 表仍为 space）；新增 REQ-KB-001 ~ 005，实现 REQ-LINK-001 ~ 003 · 005；迁移 0010（`space_groups`、`spaces.group_id`）、0011（`entries.parent_id` / `tree_order`）。

## 背景

用户（2026-09-26）：把工作台当「知识库」来用——简斋（jianzhai）、衔枝（xianzhi）各是一个产品知识库，沉淀 Bug 修复与产品迭代；其上需要大类（产品开发 / 技术学习规划 / 生活……）。

调研：
- 衔枝现状是扁平的「工作区 → 空间 → 记录 / 任务」：无大类、空间首页是任务看板、记录只有卡片网格、无层级；links 表已建但无接口，反链页签为占位。
- 简斋是「大类 → 知识库 → 文件夹树 → 文档」：4 个大类、17 个知识库，全是技术学习资料；**没有**带字段的 Bug / 迭代记录，开发历史都在应用外（CHANGELOG、记忆文件、`debug/`）。简斋的教训：目录拖拽接口从未接到前端（死代码）、面包屑不含文件夹、文档类型靠推断误判、可见性层级过多。
- 衔枝已有 kind + fields（严重度 / 状态 / 版本 / 提交），正好补上简斋缺的那一块。

## 决定

经提问，用户裁定：

1. **自定义大类**：新表 `space_groups`（工作区共享、管理员维护），空间可挂到一个大类（`spaces.group_id`，可空 = 其他（未归入大类）；个人空间不入大类）。预置「产品开发 / 技术学习规划 / 生活」，可改名 / 改色 / 排序 / 删除；删除大类不删分类。**空间类型保留**，改为可修改，用于决定概览页形态。
2. **界面改称「分类」**：大类之下这一层（简斋、衔枝……）在侧栏、页面、按钮、提示里统一叫「分类」；代码、API、表名仍为 space。不属于任何大类的归入「其他」（避免「未分类的分类」）。（注：同日先定名「知识库」，用户随即改为「分类」。）
   > 注 2026-09-26：已由 ADR-0013 改回「空间」（大类 → 空间 → 记录；不属于大类的显示「未分类」）。
3. **分类内 = 类型视图 + 目录树**：
   - 进入分类默认「概览」（`/spaces/$slug/home`）：产品型（project / work）= 未关闭 Bug 按严重度 · 最近迭代 · 最新版本 · 决策与优化 · 最近更新；学习型 = 学习计划进度 · 最近笔记 · 最近更新；快捷新建带好类型与内置模板。原任务看板 URL 不变，作为「任务」页签。
   - 记录页：类型多选、按 fields 过滤（`fields=status=open|fixed,severity=high`，服务端 jsonb 过滤）、卡片 / 表格两种视图；表格列 = 所选类型的 fields，列头排序（枚举按定义顺序）；卡片显示关键字段与标签；记录「属性」可编辑标签。
   - 目录树：`entries.parent_id` + `tree_order`（null = 不在目录）；产品库里的大量 Bug 不强制入目录，「其余记录」可一键加入。拖拽（水平位移改层级）与按钮（上移 / 下移 / 缩进 / 取消缩进 / 移出目录）**前后端全链路**；防环；软删父页或移到别的分类时子页上移一级；记录页面包屑显示完整路径。
4. **关联**：实现 `/links` 与 `/entries/:id/backlinks`；正文里的 `[[链接]]` / 记录卡片在派生时同步为 `mentions`（与 rebuild 同一路径）；反链逐条 `can(read)` 过滤。约定「迭代 / 变更 → Bug」`resolves` = 本期修复：迭代 / 变更页「本期修复的 Bug」，Bug 页「修复于」。
5. **不导入历史**：`debug/`、CHANGELOG、git log 导入暂不做；简斋的学习分类留在简斋，衔枝只放链接。

## 候选与否决

- **大类 = 可扩展的空间类型**：不加表，但大类与首页形态绑死——否决。
- **保持「空间」叫法 / 叫「知识库」**：用户最终选「分类」（候选还有 巢 / 卷 / 簿 / 项目）。
- **只做类型视图 + 标签 / 简斋式文件夹表**：用户选「类型视图 + 目录树（记录可嵌套）」；记录本身可嵌套比文件夹更贴近语雀 / Notion 的页面树。
- **所有记录强制入目录**：产品库的 Bug 数量大，目录会被淹没——改为可选入目录 +「其余记录」。
- **历史导入（debug / CHANGELOG / git log）**：用户暂不做。
