# ADR-0044 任务页 2.0：个人清单 · 更强的添加 · 清爽工具感

> 状态：已采纳 · 2026-10-01 · 修订 ADR-0043 §B（`~名` 只匹配空间 → 先匹配本人清单再匹配空间；快速添加只收文字 → 另有框内按钮与展开卡片）、§C（单栏按日期分组 → 三栏 + 智能清单 + 分组方式）、REQ-MOBILE-001（底栏「收件箱」→「任务」）。迁移 0026。需求区 00：REQ-TASK-029 ~ 036；REQ-TASK-026 · 027、REQ-MOBILE-001 加注。

## 背景

用户（2026-10-01）看过任务页后：「1、都不支持分类 2、添加任务的方式也比较傻瓜 3、样式 / UI 设计 / 动效颜色等都需要优化」。

截图（1440 / 390，亮 / 暗）暴露的问题：宽屏居中一窄条两侧大面积空；没有任何分类导航；「200 项未完成」其实是分页上限；灰色方勾选框 + 上下箭头表示优先级；空间只是小圆点；分组标题弱；快速添加是平输入框 + 说明文字；详情是覆盖式抽屉，宽屏不能边看列表边改；移动端底栏没有任务。

用户当场拍板：

1. 分类 = **新建个人「清单」**（含文件夹、智能清单、标签），而不是拿空间 / 大类或标签当分类。
2. 添加 = 输入框内按钮 + 组内就地添加 + 展开式卡片 + 全局快捷键，四项都要。
3. 视觉 = 「清爽工具感」：三栏、按优先级着色的圆形勾选圈、彩色日期胶囊、勾选动画。

## 决定

### A. 数据与接口（迁移 0026；01 §3.7b；02 §9）

1. `task_lists(id, workspace_id, owner_id, kind list|folder, parent_id?, name, color?, sort_key COLLATE "C", created_at, updated_at)`：按人私有（同标签 ADR-0017）；唯一 `(workspace_id, owner_id, kind, name)`；文件夹无色、只装清单、深度 1（check + service）；每人 ≤ 200（07 §5）。
2. `task_list_items(task_id, user_id, list_id)` PK `(task_id, user_id)`：**归类按人一行**。审查时发现若在 tasks 上放单个 `list_id`，任务指派给他人后对方清空 / 改归类会冲掉主人的分类，故改为按人映射（同 task_tags 按人过滤的思路）。
3. 语义：只能归进本人的清单（422 path `listId`）；只给 `listId` 的 PATCH 只需可读、不查乐观锁、不改 `tasks.updated_at`（私人分类不该让别人的列表重排或 409）；视图 `list` 只连本人那一行（`selectJoined` 左连，零额外查询）；删清单 → 归类级联删除，任务不动；删文件夹 → 其下清单回到根；删号时一并删除。
4. authz：+`task_list.create`（非 guest）、`task_list.manage`（`TaskListRef{ownerId}` = 本人，管理员不例外），矩阵测试齐。
5. `GET /tasks` +`listId=<uuid>|none`（`exists` / `not exists` 子查询，`withTotal` 可复用、查询数不变）；看具体清单时以「在我的这个清单里」替代 `mine()` 人员条件（归进清单的任务即使指派给别人也在清单里）；+`due=tomorrow|next7`（服务端按用户时区算边界，前端不换算）。
6. `GET /tasks/counts`：`{ all, today, tomorrow, next7, overdue, unlisted, lists }`；`today` 与 `view=today` 同口径（含子任务，与今日页一致），其余同 `view=mine`（顶层）；两条 SQL（count filter + 清单 group by）。缓存键在 `['tasks','counts',…]` 下，随任务实时失效刷新；清单增删改无空间、不走实时，本地变更后自行失效（他端需刷新）。
7. 顺带修复：`patchTaskSchema` 由 `createTaskSchema.partial()` 派生，zod 4 下 `status` / `priority` 的 `.default()` 仍会补值——**只改标题的 PATCH 会把状态改回 inbox、优先级清零**（既有缺陷）。PATCH 显式无默认；回归测试 REQ-UI-022（debug/2026-10-01-task-patch-defaults）。

### B. 任务页布局（08 §2.3b）

8. 三栏：清单栏（≥ lg，240px）· 列表 · 详情（≥ 1440 常驻右栏，`TaskDetailSheet variant="panel"`，同一份内容；更窄仍用 Sheet——e2e 桌面宽 1280 走 Sheet，不破坏既有用例）。
9. 清单栏：智能清单（全部 · 今天 · 明天 · 最近 7 天 · 未归类 · 已完成）+ 我的清单（文件夹可折叠；⋯ 改名 · 改色 · 移到文件夹 · 删除；「+」就地新建清单 / 文件夹）+ 标签（默认前 12 个）。选中 = selected 底 + 左侧主色条（同任务行焦点语言）。< lg 收为页头上方横向胶囊条。
10. search：`view | list | tag`、`group=date|priority|none`、`task`、`spaceId`（空间筛选挪到页头）。页头 = 清单名（带色点）+ 未完成数（来自 counts，不再是分页长度）。
11. 命名：「未归类」（不叫「收集箱」，避免与「收件箱」= status inbox 撞名）。

### C. 添加（REQ-TASK-032 · 033）

12. `QuickAddTask` 三种形态：full（页顶）· compact（组内就地添加：无按钮、带组预设）· dialog（全局 `c`：回车建好即关闭、Toast 可「打开」、无页面上下文进收件箱，保留 `new-task-dialog` / `new-task-input`）。
13. 框内按钮：日期（今天 / 明天 / 下周一 / 无日期 + 月历 `MiniMonth` + 时间）· 优先级 · 清单（本人清单 + 就地新建）· 标签（`TagPicker trigger`）；按钮选择优先于文字识别；生效顺序 页面默认 < 组预设 < 识别 < 按钮。识别胶囊与 × 取消照旧（REQ-TASK-026）。
14. 展开卡片：Shift+回车 /「展开」→ 多行备注（每行一段落写入 `descriptionPm`）+ 子任务行；Ctrl / ⌘+回车提交，父任务建好后逐条 `POST parentId`。
15. 移动端：底栏「收件箱」→「任务」；任务页右下浮动「+」（位于底栏与安全区之上）打开同一对话框。
16. 拖拽（REQ-TASK-036，同日用户追加，三种落点都要）：任务行（鼠标，移动 6px 才算拖；触屏不拖，留给左滑完成 / 右滑改期）拖到——左栏清单 → 归入（只改本人归类）；左栏「未归类」→ 移出清单；左栏「今天 / 明天」或列表的「今天 / 明天」组 → 截止改到那天（保留原时刻，无则 23:59）；「无日期」组 → 清空截止；按优先级分组时的某组 → 改优先级。拖动中空的可落分组也露出来（「松手放到这里」）。碰撞按指针所在落点判定（`pointerWithin`：被拖的是整行宽的行，按矩形相交会被大分组抢走）。dnd-kit 的监听只挂在虚拟行外壳上，不加 role / tabIndex，网格语义与键盘操作不变；键盘用户用详情的「清单」/ 截止 / 优先级字段完成同样的事。

### D. 视觉与动效（不变量 5）

17. `TaskRow`（全站共用）：圆形勾选圈，边框与 8% 浅底按优先级（04 §2.1：低 info · 中 primary——描边用 `primary-text`，填充仍只用 primary · 高 warning · 紧急 danger），悬停外晕、按下微缩；勾选仍为 primary 渐变 + 勾线描画，之后沿用 400ms 淡出折叠。勾选圈用 `data-check-priority`（`data-priority` 留给行尾 `PriorityIcon`，REQ-TASK-009 的选择器不变）。行尾：优先级旗标 · 本人清单色点与名 · 标签 · 空间 · 日期胶囊（逾期 danger-soft · 今天 success-soft · 明天 info-soft · 7 天内 primary-soft · 更晚灰）· 「有详情」标记。
18. 分组头粗体 + 计数胶囊 + 旋转箭头；组体 `xz-rise` 入场；快速添加框聚焦外晕；识别胶囊弹入；详情栏右侧滑入。减弱档一律改为短淡入（无位移）；新增类只取 token，无 `!important`、无新 `backdrop-filter`。

## 候选与否决

- **空间 + 大类当清单**：不加表，但每个分类都得建一个团队共享的「重」容器，侧栏空间列表更乱——用户否决。
- **标签当分类**：改动最小，但一个任务多标签、分类不唯一、无文件夹层级——用户否决。
- **tasks 上单列 `list_id`**：审查发现共享任务上会互相覆盖归类——否决，改按人映射表。
- **输入框内高亮镜像层**（识别文字在框内着色）：输入法组词与横向滚动下不稳，且与 × 取消的交互重复——否决，保留框下胶囊。
- **≥ 1280 常驻详情栏**：1280 下 应用侧栏 240 + 清单栏 240 + 详情 ~400 只剩 ~400px 给列表，且 e2e 桌面宽即 1280——改为 ≥ 1440。
- ~~**拖任务到左栏清单**：下一轮~~（同日用户要求本轮完成，见 §C.16）。
- **清单共享 / 协作清单**：同日再次确认本轮不做（协作走共享空间的指派 / 关注 / 评论）。
- **键盘拖拽**（dnd-kit KeyboardSensor）：与任务列表的 j / k / 空格冲突——不做，用详情字段替代。
- **清单内分节（section）、重复任务**：本轮不做。
