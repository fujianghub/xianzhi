# ADR-0039 模板元数据：模板自有字段 · 移除类型字段 · 记录记住来源模板

> 状态：已采纳 · 2026-09-30 · 修订 ADR-0036 §A.5 · §E.29（模板只能「预填」所绑类型的字段、要加属性只能改类型 → **模板有自己的元数据**）、ADR-0011 §2（模板只在新建时用一次、记录不记来源 → 记录带 `template_id`）、ADR-0038 §1（内置模板覆盖的列 +`field_defs` `hidden_fields`）。迁移 0024。需求区 00：REQ-TPL-016 ~ 019、REQ-ENTRY-032；REQ-TPL-004 · 007 · 011 加注。

## 背景

用户（2026-09-30）：「模板支持元数据自定义，增、删、改、查，不要只是添加；其他相关模块也需要做适配」。

ADR-0036 把字段定义挂在**类型**上，模板只预填值。落到模板编辑页上的实际体验：

- 绝大多数模板绑的是内置类型，而内置类型只能由所有者**追加**字段，代码字段（模块、提交、踩坑目录…）删不了；
- 成员对自己的模板什么都定制不了（没有类型管理权限，只能填预填值）；
- 在模板页里改的其实是类型，影响该类型的**全部**记录——「读书笔记」想要「作者」，结果所有随笔都多出「作者」；要避开就得先去建一个类型再回来绑，两处来回。

## 决定

模板有自己的元数据：**自有字段**（增删改）+ **移除的类型字段**；用模板建出的记录记下**来源模板**，其有效字段 = 类型字段 − 模板移除的 + 模板自有的。类型上的字段定义（ADR-0036）不变，仍是「这一类记录都有的属性」。

### A. 数据（迁移 0024；01 §3.4）

1. `entry_templates + field_defs jsonb default '[]'`：模板自有字段，`FieldDef`（同 ADR-0036 §A.6：x 键、8 种类型、选项与色、必填提示），≤ 20 个、模板内名不重复。
2. `entry_templates + hidden_fields jsonb default '[]'`：本模板移除的类型字段名。
3. `builtin_template_overrides + field_defs jsonb? + hidden_fields jsonb?`（null = 代码默认 = 都为空）。
4. `entries + template_id text?`：来源模板，`builtin:<key>` 或用户模板 uuid；无外键（代码内置模板不入表，同 `spaces.default_template_id`）；partial index `where template_id is not null`。`builtin:blank` 只是「不要骨架」，不记。
5. `AUDIT_ACTIONS + template.fields_changed`（`pnpm db:generate` 重建 check）。

### B. 语义

6. **来源模板**在 `POST /entries {templateId}` 时写入，之后不可改；改类型、移动、合并空间都保留。斜杠 `/模板` 插入正文、按类型默认骨架**不**设置来源模板；已有记录不能事后「套」一个模板的元数据。
7. **自有字段与类型无关**：模板之后换绑类型，已建记录仍认这些字段；记录改了类型，自有字段值保留（`fieldsForRetype` 保留 目标类型 ∪ 来源模板 的同键值）。
8. **移除（hidden）只影响展示与预填**，不动记录里的值：被移除的字段不出现在属性面板、表格单元格、新建表单、模板预填里。
   - 可移除 = 类型的可省内置字段，**去掉**进流转的（状态 / 优先级 / 严重度——统计、看板、流转靠它们）与服务端维护的 Bug 发现 / 解决日期；外加类型的自定义字段（x 键）。必填字段不可移除。
   - 只在**记录的类型与模板所绑类型一致**时生效（记录改过类型后，同名字段在新类型里可能是必填的）。
   - 保存时不认识的名字静默丢弃（类型之后可能变）；模板换类型且未给 `hiddenFields` → 清空。
9. **x 值校验**（`resolveKindFields`）：合法的自定义字段 = 类型的 ∪ 来源模板的（同键以类型为准）。未定义的键仍静默丢弃——不带模板新建时带了模板字段的键，不会 422，也不会落库。
10. **自有字段的键由服务端生成**。输入里「不在原定义中的键」只是客户端的临时句柄（好在同一次保存里给新字段预填值），服务端一律换成自己生成的键并改写同一请求里的 `fields`。不让客户端挑键：否则可挑一个与某类型字段相同的键，日后删这个模板字段时（第 11 条）连带清掉那些记录里的类型字段值。新键也不与所绑类型的字段键相同；新增 / 改名的自有字段不得与所绑类型的自定义字段重名（同一条记录上两个同名属性）。
11. **改自有字段定义**（`PATCH` 的 `fieldDefs` 整组替换 + `optionRenames`）同事务同步 `template_id = 该模板` 的记录（含回收站），规则同 ADR-0036 §A.11：删字段清值、选项改名同步、删选项清值（单选去键、多选去该项）、字段类型不可改。模板自己的预填 `fields` 按同规则迁移后再校验。有记录被改 → 审计 `template.fields_changed`。不写流转、不改 `entryQuery` / 保存视图里的条件。
12. **删模板**：
    - 用户模板 / 所有者新增的内置模板（硬删）：同事务清掉引用它的记录里自有字段的值、`template_id` 置空，审计。
    - 代码内置模板软删：不动（覆盖行仍在，旧记录照常显示这些属性；恢复即恢复）。
    - 代码内置模板「恢复默认」：自有字段回到代码默认（没有）→ 同事务清引用记录里的值（`template_id` 保留），审计。
    - 删号（`purgeUser`）：仍被记录引用的个人模板**保留**（否则留下来的记录丢属性）；它不再出现在任何人的模板列表里，只经第 14 条的目录生效。
13. **沿用**：「复制到我的」复制自有字段（键不变，值可互通）与移除清单；「另存为模板」沿用该记录来源模板的元数据（能读记录即可，不要求能读那个模板）。类型被删、模板转随笔时：移除清单清空，自有字段及其预填保留。
14. **可见性**：`GET /templates/fields` 返回读者「认得」的模板元数据目录（只含有自有字段或移除了字段的）`[{ id, kind, typeId, fieldDefs, hiddenFields }]`：
    - 自己可读的模板（`template.read`；代码内置含已软删的）；
    - **别人的个人模板**：仅当存在读者可读的记录（`visibleEntriesWhere`，或读者回收站里的）引用它——看得到记录就该看得懂它的属性。只给定义，不给模板名 / 正文 / 作者；`GET /templates/:id` 仍 404。
15. **权限**：不新增 action。改模板元数据 = `template.manage`（作者 / 管理员；内置仅所有者）。成员定制自己模板的元数据不需要类型管理权限。

### C. API（02 §9）

16. `POST /templates`、`PATCH /templates/:id`：+`fieldDefs?` `hiddenFields?`；`PATCH` 另 +`optionRenames?`。
17. 模板视图（列表 / 详情）+`fieldDefs` `hiddenFields` `entryCount`（引用它的记录数，含回收站，仅计数）。
18. +`GET /templates/fields`（注册在 `/:id` 之前）。
19. 记录视图（详情与列表）+`templateId`。
20. 导出 frontmatter 把 x 键换成字段名时并入来源模板的定义。

### D. 前端（08 §2.13 · §2.9 · §3.2）

21. `useFieldSpecs()(kind, typeId, templateId?)`：给了来源模板就套上模板元数据（`withTemplateSpecs`）。属性面板、卡片、表格按行传 `entry.templateId`。
22. **表格**（单一类型时）：已加载行的来源模板带来的自有字段各占一列，附在类型字段之后；某行没有这个属性显示 `—`、不可编辑。
23. **新建对话框**：选了模板 → 属性表单去掉它移除的类型字段、追加它的自有字段（快速提 Bug 的精简表单仍只列优先级 / 严重度 / 模块，其中被移除的不列）。
24. **模板编辑页「元数据」区**（取代「字段预填」）：
    - 类型属性：预填值；可移除的行末有「×」，移除后收进「已移除 N 个」并可恢复；不可移除的显示锁。
    - 模板属性：`FieldDefsEditor`（名、类型、必填、选项与色、上下移、删除）+ 每个字段下的预填值；「添加属性」。
    - 随模板「保存」一起提交；有记录在用且删了字段 / 选项 → 先确认（写明条数与将清空的项）。
    - 底部「编辑类型本身的字段」（ADR-0036）保留。
25. 模板列表行写明「模板属性：…」「已移除：…」；预览对话框在正文上方列出属性与预填值；删除 / 恢复默认的确认框在会清值时写明条数。
26. 422（字段定义可能已变）时顺带失效 `['templates','fields']`。

## 候选与否决

- **只把类型字段编辑器做得更显眼**：成员仍无权限、内置字段仍删不了、改动仍波及全类型——不满足。
- **记录上存字段定义快照**：模板改名 / 改选项不传播，同模板的记录之间筛选口径漂移，列表负载变大——否决，用引用 + 同步。
- **模板级改内置字段的名 / 选项**：内置字段的值受 strict zod、流转与统计约束；只改显示名又让表格同一列两种叫法——不做，内置字段只支持移除 / 恢复 / 预填。
- **必填或进流转的字段也可移除**：迭代 / 变更 / 复盘的必填无默认值，新建会 422；状态被藏起来的 Bug 永远停在「新建」污染统计——否决。
- **客户端生成字段键**：见第 10 条。
- **模板字段并入记录页筛选 / 分组选项**：同一类型下不同模板的记录混在一个列表里，分组键只对其中一部分有意义——本轮不做；`fields=` 筛选参数本身已支持任意 x 键。
- **模板元数据变更的实时推送**：与类型字段定义（ADR-0036）一致，不推；靠 60 秒缓存过期与 422 时失效。

## 后果

- 迁移 `0024`：`entry_templates` +2 列；`builtin_template_overrides` +2 列；`entries` +`template_id` 与 partial index；`audit_log_action_ck` +`template.fields_changed`。存量记录 `template_id` 为空（行为不变）。
- 00：+REQ-TPL-016 ~ 019、REQ-ENTRY-032；REQ-TPL-004 · 007 · 011 加注。01 §3.4（entries · entry_templates · builtin_template_overrides）· §3.12。02 §9。08 §2.9 · §2.13 · §3.2。glossary +模板属性 · 来源模板 · 移除（类型属性）。
- 删模板不再是「已建记录不受影响」：有自有字段时会清值（确认框写明）；代码内置模板的软删不受此影响。
- 表格里同一类型、不同模板的记录会出现「这一行没有这一列」的 `—`。
- 已知限制：代码里日后去掉某个 `builtin:<key>` 时，它的覆盖行（含自有字段定义）成为孤儿，引用它的记录的模板属性不再显示（值仍在库里）。
