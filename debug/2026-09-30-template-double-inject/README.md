# 新记录的正文模板重复出现两份：未落库时离开再打开，服务端再注入一次，与本地缓存合并

> 2026-09-30 · 03 §6 · 不变量 7

## 症状

- 通过 API 或新建对话框建一条 Bug 后打开，很快离开，再打开：大纲里「症状 · 复现步骤 · 根因 · 修复 · 验证」出现两遍，摘要也重复。
- 只有「首次打开后还没编辑、没落库」就离开的记录会这样；编辑过一次（ydoc_version ≥ 1）的不会。

## 复现

1. 建一条记录，`ydoc_version = 0`、正文为空文档。
2. 打开记录页：collab `onLoadDocument` 见空文档，注入按类型的模板骨架。客户端把状态写进 y-indexeddb。
3. 不编辑就离开：没有改动，不触发 `onStoreDocument`；最后一个连接关闭后服务端卸载文档，库里仍是空文档、`version = 0`。
4. 再打开：服务端又注入一次；客户端从 y-indexeddb 同步上次的状态过来。两次注入各有一套 Yjs 条目（clientID 不同），合并后骨架变成两份。

## 根因

- 注入用的是服务端文档自己的随机 clientID。两次加载的 clientID 不同，Yjs 把两次注入的条目当成不同内容，无法去重。
- 「只在从未落库的空文档注入」只挡得住已落库的文档，挡不住本地缓存里的上一次注入。

## 修复

- 注入改为确定性（`src/collab/server.ts` 的 `templateUpdate`）：
  - 模板先写进一个临时 `Y.Doc`（`gc: false`），它的 clientID 由记录 id 派生（FNV-1a 32 位，`templateClientId`）。
  - 从空文档开始，时钟从 0 起，再把 update 应用到服务端文档。
  - 同一记录、同一类型、同一 locale，每次注入得到**同一批条目 ID 与内容**。与本地缓存合并时，Yjs 按 ID 去重。
- 没有改成「注入后立即落库」：那样要走 `storeDocument`（派生、快照、事件），还要在 `saveMutex` 内（不变量 7），代价大于收益。
- 残留边角：两次加载之间改了类型或 locale，两次注入的内容不同，仍会并存。这种情况极少，可以接受。
