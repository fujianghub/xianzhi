# 日历任务气泡：回车存标题后紧接着改时间被 409 冲掉；日历 e2e 因共用库同时段数据被「+N」收起

- 日期：2026-09-27
- 影响范围：client（日历快速编辑气泡）· e2e
- 严重度：medium
- 相关：ADR-0016 · REQ-CAL-012 · REQ-CAL-011 · debug/2026-09-26-e2e-shared-db-data-drift

## 症状
1. 日历里点任务弹气泡，改标题回车，再把时间改成 16:00：标题改了，时间仍是 15:00，并弹「任务已被他人修改」。
2. 对共用库 `xz_e2e`（不重建）跑 `e2e/calendar.spec.ts`：REQ-UI-031 找不到今天 14:30 的任务块、REQ-CAL-005 5 次重复只看到 1 次。

## 复现
1. 在气泡标题框改字 → Enter → 立刻改时间输入框。
2. 同一个库上把 calendar.spec.ts 连跑几轮（每轮都在「今天 14:30」建任务、在 2026-11-23 07:00 建每日重复日程）。

## 根因
1. 标题框 `onKeyDown(Enter)` 与 `onBlur` 都调 `saveTitle()`；焦点移到时间框触发第二次保存。两次 PATCH（以及紧随的改时间）都用气泡打开时那份任务的 `updatedAt` 作 `ifUpdatedAt`，第一次成功后其余都 409；409 分支把缓存与气泡回滚为服务端当前值，改时间随之丢失。
2. REQ-CAL-011 起周视图同一重叠簇最多并排 2 列、其余收进「+N」。用例固定日期 / 时段，历次运行留下的同名同时段数据越积越多，被测项落进「+N」而不可见——与 debug/2026-09-26 同一类数据漂移。

## 修复
1. `src/client/components/calendar/QuickEdit.tsx` TaskQuick：写操作进一条 Promise 队列串行执行，每次都以 `latest.current`（上一次成功返回的任务）为基准；标题记下「已排队未落库」的值，回车 + 失焦只提交一次。
2. `e2e/calendar.spec.ts`：按时间戳挑「2027 年起第 k 周的周一」与 06:00–19:55 的 5 分钟时段；新用例结束时删掉自建任务。

## 验证
- e2e（对本 worktree 3031 实例、共用 `xz_e2e`、不重建）：calendar.spec.ts 10 条全过，其中 REQ-CAL-012 · 013 覆盖「改标题回车 → 改时刻 16:00 → 块移到 16:00」。
- 残余：随机时段仍有极小概率与其它用例今天建的任务同时段；若再现，看失败快照里是否出现「同一时段还有 N 项」。
