# 日期属性点了改不了：原生日期框逐段 change 即提交，存进半截日期

- 日期：2026-10-09
- 影响范围：client · server
- 严重度：high
- 相关：ADR-0056 §A；REQ-ENTRY-042（修订 REQ-ENTRY-024 / 026 的日期编辑）

## 症状

Bug 的发现日期（以及所有日期属性：迭代起止、自定义 date 字段、表格单元格、详情坞）点开后一按键 / 一改就关掉，值变成别的日子；键入年份时甚至存进 `0005-02-02`。只有点输入框右侧那个淡色小日历图标才能正常选。

## 复现

1. Bug 记录 → 属性面板点「发现日期」，弹层里光标自动落在月份段。
2. 按一次 ↓ → 立即 PATCH `foundAt=2026-09-09`，弹层关闭。
3. 重开、点进年份段键入 `2025` → 连发三次 PATCH（`2026-02-09` → `2026-02-02` → `0005-02-02`），最终存进 `0005-02-02`。

## 根因

`FieldValue.tsx` `InputEditor` 用 `<input type="date">`，`onChange` 里「有值即 `onCommit` 并关弹层」——本意是「日历选中即提交」。但 Chrome 的日期框按段编辑，**每改一段都触发 change 且值已是完整合法日期**（未改的段沿用旧值，年份按已键入位数解析成 0005 之类），于是第一次按键就提交关闭，余下按键落在退场中的输入框上继续提交。服务端 `isoDate = z.iso.date()` 只验格式，`0005-02-02` 也 ≤ 今天，照收。

## 修复

- 日期分支改为 `DateFieldPicker`：快选 + 月历（复用 `MiniMonth`）点即提交；文本框只在回车时按完整日期提交，半截 / 越界就地提示。
- `entryFields.dateBounds()` 按日期先后约束与「发现日期 ≤ 今天」推出范围，越界日期置灰。
- 服务端 `isoDate` 加年份 1900 ~ 2999。

## 验证

- unit `src/shared/__tests__/entryFields.test.ts`：REQ-ENTRY-042 两条（0005 / 3000 年被拒；dateBounds 各组合）。
- e2e `e2e/bug.spec.ts` REQ-ENTRY-042：键入 `2025` 无 PATCH 且弹层不关、回车提示；完整日期回车一次 PATCH；月历点今天再一次 PATCH；「明天」置灰。
- 已查本机库 `xz`：没有 1900 年前 / 2999 年后的日期值，无需修数据。
